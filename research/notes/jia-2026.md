# Notes: jia-2026

> Jia, M., Diaz-Rodriguez, J. (2026). Unsupervised Text Segmentation via Kernel
> Change-Point Detection on Sentence Embeddings. arXiv:2601.18788 (v1).
> Companion theory paper: [diazrodriguez-2025] (arXiv:2510.03437).

## Summary

**Embed-KCPD**: embed each sentence with a fixed sentence encoder, then find
boundaries by minimising a penalised kernel change point detection (KCPD)
objective with PELT. Training-free and prompt-free. The paper also proves
consistency guarantees for penalised KCPD when the sequence is m-dependent
(short-range dependence, as between adjacent sentences).

## Method

- Units `X_1..X_T` (sentences / paragraphs / turns) → embeddings `Y_t = f(X_t)`.
- Block cost (within-block dispersion in RKHS):
  `C(s,e) = Σ k(Y_t,Y_t) − (1/(e−s+1)) Σ_i Σ_j k(Y_i,Y_j)`.
- Objective: `Σ_k C(τ_{k−1}+1, τ_k) + β_T · K`, minimised exactly with PELT
  (linear time under mild conditions).
- Penalty `β_T = C · sqrt(T log T)`; a single global `C` is picked by an
  unsupervised elbow method (C ≈ 0.088 cosine, 0.06 RBF), and results are
  reported stable over a range of C.
- Kernels: RBF (satisfies the theory) and cosine (does not, but works better
  in practice on most datasets).

## Theory (§4)

Under m-dependence + within-block stationarity, bounded characteristic kernel,
minimum spacing and penalty conditions:

- Oracle inequality for the population penalised risk (Thm 4.11).
- No spurious splits inside homogeneous blocks w.h.p. (Prop 4.10).
- Localisation: every true change point is recovered within `δ_T ≍ sqrt(T log T)`
  (Thm 4.12) — small relative to segment length as T grows.

The authors are explicit that the assumptions are a stylised proxy and the
rates are conservative, not tuning rules.

## Results

- Choi dataset: Pk ≈ 3–6, competitive with the best unsupervised baselines.
- Wiki-300 / Wiki-50 / Elements / arXiv: beats TextTiling, GraphSeg, Coherence
  (and TextTiling with modern embeddings) on most settings. Wiki-50 Pk ≈ 38–42
  vs supervised CATS/TextSeg ≈ 16–18, so a gap to supervised remains.
- Simulation with GPT-4.1-generated m-order Markov text confirms Pk/WD fall as
  T grows; insensitive to m.

## Key findings relevant to chunklabel

- **The CPD machinery we want, already validated on text.** The cost function
  is pluggable: swapping the kernel cost on embeddings for a Gaussian/mean-shift
  cost on a surprisal series (or concatenating both) is a small change in a
  library like `ruptures`.
- The penalty-scaling rule `C · sqrt(T log T)` plus elbow selection gives a
  label-free way to choose the number of chunks — currently implicit in the
  LLM prompt.
- Output is a set of sentence indices → extractive by construction.
- Cosine-kernel on embeddings is a strong, cheap baseline to compare a
  surprisal-based series against.

## Limitations

- Needs a sentence splitter; boundaries can only fall on unit edges.
- Assumes within-block stationarity; texts with gradual drift violate it.
- Minimum segment length assumption excludes very short chunks, which
  chunklabel's examples (one-sentence chunks) often have.
- Benchmarks are topic segmentation; finer "functional" segments (as in
  chunklabel's initiation / obstacle / outcome example) are not evaluated.

## Actionable ideas

- Use Embed-KCPD (cosine kernel + PELT) as the embedding baseline in
  `ideas/surprisal-cpd-boundaries.md`.
- Adopt the `C · sqrt(T log T)` penalty with elbow selection as the default
  way to set the number of boundaries.
