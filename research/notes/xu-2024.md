# Notes: xu-2024

> Xu, D., Chen, W., Peng, W., et al. (2024). Large language models for generative
> information extraction: a survey. *Frontiers of Computer Science*, 18(6), 186357.
> arXiv:2312.17617.

## Summary

A systematic survey of how LLMs are applied to information extraction (IE) tasks
(NER, relation extraction, event extraction). The paper taxonomizes output formats,
prompting strategies, and model architectures, and identifies which combinations
work best for which task types.

## IE task taxonomy

| Task | What is extracted |
|------|------------------|
| NER | Entity spans + type labels |
| Relation extraction (RE) | Entity pairs + relation type |
| Event extraction (EE) | Event trigger + argument roles |
| Universal IE | All tasks jointly |

chunklabel is closest to **span extraction + classification**: extract a verbatim
quote (span) and assign a free-form category (type label). This is structurally
NER with open categories and no predefined type set.

## Output format paradigm

**Natural-language-based (NL-LLMs):** Output structured data as formatted text.
UIE, InstructUIE: "text-to-structure generation" with templated textual schemas.
- Pros: concise prompts, easy to design
- Cons: less rigorous structure, more parsing failures

**Code-based (Code-LLMs):** Output Python class definitions or code.
Code4UIE, GoLLIE: use Python dataclass schemas.
- Pros: formal syntax enforces structure, better for strict RE
- Cons: larger context, requires the model to understand Python

chunklabel currently uses **NL-based JSON** (structured output via function calling).
The survey suggests code-based formats may outperform NL for strict structural tasks.

## Prompting strategy taxonomy

| Strategy | How it works |
|----------|-------------|
| QA-style | Reformulate IE as question answering |
| Chain-of-Thought | Step-by-step reasoning before extraction |
| Self-improvement | Iterative verification and correction of outputs |
| Zero-shot | Generalize without task-specific examples |

**Key result:** Supervised fine-tuning consistently outperforms zero-shot. However,
CoT and self-improvement close much of the gap in zero-shot settings.

## Key findings relevant to chunklabel

**chunklabel is a zero-shot open-schema NER task.** The survey's findings for
zero-shot NER apply directly:
- CoT prompting helps the model reason about span boundaries before committing
  to a quote. Adding a reasoning step ("first identify topic changes, then quote
  the relevant span") could reduce alignment errors.
- Self-improvement: after generating chunks, prompt the model to verify that each
  quote is verbatim and that no text is double-covered. This maps to the alignment
  step.

**Open category schema is the hardest setting.** Most IE systems use a closed type
set. chunklabel's free-form categories make normalization essential (the Normalizer).
The survey notes that universal IE models with a closed schema outperform open-schema
ones — confirming that category normalization is a genuine bottleneck.

**Output format ablation is motivated.** The survey shows that NL vs code formats
produce meaningfully different results. The ablation proposed in
`ideas/prompt-format-ablation.md` (quote-first vs category-first vs schema-explicit)
is directly supported as a valid experimental design.

**Three prompt variants to compare** (directly from the survey's framework):
1. Current (quote-first, NL JSON) = NL-LLM, zero-shot
2. Category-first = different NL ordering
3. Function-calling JSON Schema = closest to Code-LLM approach

## Limitations

- Survey covers published literature up to mid-2023; more recent LLM-native
  approaches (GPT-4o structured output, Claude tool use) are not covered.
- Does not cover span alignment as a separate post-processing step; chunklabel's
  rapidfuzz alignment is out of scope.
- Evaluation is across many domains and models; results are not specific to
  free-form category extraction.

## Actionable ideas

- Add a CoT reasoning step to the chunklabel prompt: "First identify where the
  topic changes, then quote the exact span for each segment."
- Add a self-verification step: after the LLM returns chunks, re-prompt with
  "Check that each quote is an exact verbatim excerpt and that together they
  cover the full text without overlap."
- Run the three-variant prompt ablation on a benchmark corpus
  (see `ideas/prompt-format-ablation.md`).
